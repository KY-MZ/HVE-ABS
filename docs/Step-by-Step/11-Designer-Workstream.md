# 11. 디자이너 작업 분리

Relationship Manager Intelligence Experience 중 **디자이너(UX/UI)** 가 담당하는 작업을 분리한 문서다. 다른 롤(백엔드, 인프라, AI, 보안)의 작업은 [10-Roadmap-and-Tracking.md](10-Roadmap-and-Tracking.md)와 각 상세 문서를 따른다.

## 1. 범위

고객 UI는 별도 웹앱이 아니라 **Microsoft 365 Copilot 안의 Declarative Agent** 이므로, 디자이너의 작업은 화면 픽셀보다 **대화 경험, 응답 구조, 인용 표현, 신뢰/오류 상태, 관리자 화면** 설계에 집중한다.

| 구분 | 포함 | 제외 |
|---|---|---|
| 포함 | Copilot 대화 흐름, Adaptive Card, 인용 UX, 빈/오류/권한 없음 상태, Managed App 배포 관리자 화면 문구, 감사 증거 뷰, 진행 대시보드 UI | 백엔드, 인프라, 모델 구현 |
| 제외 | Copilot 자체 UI 커스터마이징 (플랫폼 제약) | 로고/브랜딩 전면 개편 |

## 2. 설계 제약 (요구사항 연결)

| 제약 | 근거 | 디자인 영향 |
|---|---|---|
| 모든 사실 문장에 citation ID, 클릭 시 원본 링크 | FR-6 | 인용 칩/번호 패턴, 원본 링크 열기 방식 |
| 근거 2건 미만이면 "근거 부족" 표시 | FR-4 | 신뢰도/근거 부족 상태 디자인 |
| 접근 권한 없는 계정은 존재 여부도 노출 안 함 | FR-7 | "권한 없음"과 "없음"을 구분하지 않는 동일 문구 |
| 응답은 요약 + 인용 링크 (토큰 한도) | 07 문서 | 짧은 카드, 상세는 링크로 드릴다운 |
| 위험 지표는 점수, 입력 근거, 산식 버전 표시 | FR-3 | 지표 카드 + 근거 펼침 |
| 일반 질의 p95 10초 | NFR-4 | 로딩/스트리밍/진행 상태 |

## 3. 산출물과 작업 분해

### D1. 사용자 리서치와 페르소나 (M1)

* RM 페르소나 2~3종, 핵심 시나리오(고객 미팅 전 준비, 주간 포트폴리오 점검, 위험 징후 확인) 정의.
* RM 5명 내외 인터뷰 가이드와 결과 요약.
* 산출: 페르소나 문서, Journey map, 시나리오 목록.
* 완료 기준: 시나리오별 성공 기준(소요 시간, 필요한 정보) 합의.

### D2. 대화 설계 (M2~M4)

* 대표 질문 20개와 기대 응답 구조(요약 → 위험 → 기회 → 다음 조치).
* 후속 질문 제안(Prompt starters), 모호한 계정명 확인 질문 흐름.
* 응답 톤/문체 가이드 (한국어, 금융 맥락, 단정 표현 지양).
* 산출: 대화 스크립트, 프롬프트 스타터 목록, 톤 가이드.
* 완료 기준: AI 담당과 평가 질문 세트(골든셋)로 공유.

### D3. 응답 컴포넌트 (Adaptive Card) 설계 (M4~M5)

* 계정 요약 카드, 위험 지표 카드(점수, 추세, 근거), 성장 기회 카드, 권장 조치 카드(조치, 이유, 담당/기한).
* 인용 표시 패턴: 번호 칩 + 출처 유형 아이콘(CRM, 이메일, 거래, 지식).
* 산출: Figma 컴포넌트, Adaptive Card JSON 초안 (OpenAPI 응답 스키마 기준).
* 완료 기준: 07 문서의 `citations[]` 스키마와 필드 매핑 확인.

### D4. 상태와 예외 UX (M4~M5)

| 상태 | 요구 |
|---|---|
| 로딩 | 10초 이내 진행 안내 |
| 근거 부족 | "근거 부족" 명시, 추측 금지 |
| 권한 없음/계정 없음 | 동일한 문구로 존재 여부 비노출 |
| 일부 소스 장애 | 어떤 소스가 빠졌는지 표시, 부분 결과 안내 |
| 데이터 오래됨 | 마지막 동기화 시각 표시 |
| 안전 필터 차단 | 이유와 대안 안내 |

* 산출: 상태별 화면 명세, 문구 사전(마이크로카피).
* 완료 기준: 07, 06 문서의 오류 코드와 1:1 매핑.

### D5. Managed App 관리자 경험 (M1, M6)

* 배포 파라미터 입력 화면(Azure Portal createUiDefinition) 그룹/라벨/도움말 문구.
* 고객 IT 관리자용 설치 후 점검 체크리스트, 운영 알림 문구.
* 산출: createUiDefinition 문구 초안, 관리자 가이드 와이어프레임.
* 완료 기준: 03 문서 파라미터 목록과 일치.

### D6. 감사 증거 뷰 (M6)

* 감사 담당자가 질의/근거/접근 결정을 확인하는 Workbook 또는 보고서 레이아웃.
* 개인정보 최소 노출 원칙(해시/ID 중심, 08 문서) 반영.
* 산출: Azure Workbook 와이어프레임, 증거 패키지 표지/목차 템플릿.
* 완료 기준: 08 문서의 로그 필드와 화면 항목 매핑.

### D7. 진행 대시보드 UI 개선 (M7)

* [dashboard.html](../../dashboard.html)의 정보 구조, 접근성(대비, 키보드), 반응형 점검.
* 산출: 개선안과 반영 PR.

### D8. 사용성 검증 (M5~M7)

* 프로토타입으로 RM 5명 사용성 테스트, 이슈 우선순위화.
* 접근성 점검(WCAG 2.2 AA 기준, Adaptive Card 한계 포함).
* 완료 기준: 치명적(severity 1) 이슈 0건.

## 6. 개발자에게 전달할 입력

* Figma 파일과 컴포넌트 명세 (Adaptive Card JSON 포함).
* 문구 사전(한국어), 오류 코드별 사용자 메시지.
* 인용 필드 매핑표: `citations[].id`, `sourceType`, `title`, `url`, `retrievedAt` → UI 요소.

## 7. 확인 필요

* Copilot 채널에서 렌더링 가능한 Adaptive Card 버전과 제한.
* 영어 병행 지원 여부(현재 한국어 우선 가정).
* RM 사용자 인터뷰 가능한 고객/인원.
