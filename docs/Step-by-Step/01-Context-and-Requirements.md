# 01. 컨텍스트와 요구사항

## 1. 이해관계자

| 역할 | 관심사 |
|---|---|
| Relationship Manager | 빠르고 근거 있는 계정 브리핑, 다음 조치 |
| 고객사 IT/보안 | 데이터 상주, 접근 통제, 감사, 학습 미사용 |
| 금융 파트너(퍼블리셔) | 반복 배포, 버전 업데이트, 지원 가능성 |
| 컴플라이언스 | 추천 근거의 추적성, 감사 증거 |
| SE/구현팀 | 명확한 계약, 재현 가능한 코드 |

## 2. 기능 요구사항 (FR)

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-1 | RM이 Copilot에서 계정 질문 | 자연어 질문에 계정 요약 응답 |
| FR-2 | CRM, 이메일, 거래, 지식 통합 인사이트 | 4개 소스 최소 1개씩 근거로 인용 가능 |
| FR-3 | 위험 지표 | 지표별 점수, 입력 근거, 산식 버전 |
| FR-4 | 성장 기회 | 기회별 근거 2건 이상 또는 "근거 부족" 표시 |
| FR-5 | 권장 다음 조치 | 조치, 이유, 인용, 담당/기한 제안 |
| FR-6 | 출처 인용 | 모든 사실 문장에 citation ID, 클릭 시 원본 링크 |
| FR-7 | 계정별 접근 통제 | 접근 권한 없는 계정은 존재 여부도 노출 안 함 |

## 3. 비기능 요구사항 (NFR)

| ID | 요구사항 | 목표 |
|---|---|---|
| NFR-1 | 고객 구독 격리 | 퍼블리셔 기본 데이터 접근권 없음 |
| NFR-2 | 학습 미사용 | 모델 학습/파인튜닝에 고객 데이터 미사용, 코드 및 정책으로 강제 |
| NFR-3 | 감사 | 모든 질의/근거/접근 결정 로그, 보존 기간 설정 가능 |
| NFR-4 | 지연 | 일반 질의 p95 10초 이내 (초안 목표, 부하 테스트 후 확정) |
| NFR-5 | 가용성 | 99.9% 목표 (영역 중복 구성 시) |
| NFR-6 | 비밀 관리 | 비밀 코드/설정 평문 금지, Key Vault + Managed Identity |
| NFR-7 | 네트워크 | 데이터 서비스 Private Endpoint, 공용 접근 차단 |

## 4. 비목표

* 모델 학습/파인튜닝, 자동 실행(고객 연락 발송 등 쓰기 작업). 1차 릴리스는 **읽기 및 추천만**.
* 퍼블리셔 중앙 SaaS 멀티테넌트 데이터 저장.
* 규제 의견 제공(법적 자문). 추천은 의사결정 보조.

## 5. 제약과 전제

* M365 Copilot 채널: Declarative agent + API plugin (OpenAPI). 참고: `Ref` 의 Decision-002 (Declarative 선택)와 같은 계열 결정을 재사용한다.
* Copilot 응답 토큰 한도가 있으므로 API는 **요약 + 인용 링크**만 반환한다.
* 고객 테넌트마다 Entra 앱 등록 및 관리자 동의가 필요하다.
