## 📋 인터뷰 목표

RPI(Research, Plan, Implement, Review) 워크플로의 진입점을 결정하고, 작업의 복잡도, 증거 준비 상태, 필요한 라이프사이클 개념을 파악합니다.

---

## 🎯 Phase 1: 준비 상태 평가 (Readiness Assessment)

### 질문 1: 작업 정의
**목표**: 요구사항, 수용 기준, 종속성, 사용 가능한 증거를 파악합니다.

```
Q1. 현재 해결하려는 작업이나 요구사항을 설명해주세요.
    - 어떤 목표를 달성하고자 하나요?
    - 성공의 수용 기준은 무엇인가요?
    
Q2. 이미 가지고 있는 증거나 정보가 있나요?
    - 기존 문서, 설계, 또는 구현 사례가 있나요?
    - 알려진 제약사항이나 의존성이 있나요?
    
Q3. 주요 불확실성이나 의사결정 사항이 있나요?
    - 아키텍처 선택이 필요한가요?
    - 기술 스택이나 패턴에 대해 검증이 필요한가요?
```

### 질문 2: 증거 격차 식별
**목표**: 조사(Research)가 필요한지 판단합니다.

```
Q4. 다음에 대해 충분한 증거가 있나요?
    ☐ 요구사항의 완전성
    ☐ 수용 기준의 명확성
    ☐ 기존 패턴 또는 솔루션
    ☐ 종속성 및 위험 요소
    ☐ 구현 전략

증거 격차 → /rpi-research 필요
증거 충분 → 다음 단계로
```

## 🔬 Phase 2: 진입 경로 선택 (Entry Path Selection)

### 의사결정 트리

| 상황 | 진입 경로 | 사용 시점 |
|------|---------|---------|
| **전체 라이프사이클 래퍼 필요** | `RPI Agent` | 사용자가 선택하는 워크플로 래퍼를 원할 때; 기본 수동, 요청 시 자동 |
| **입증된 증거 격차** | `/rpi-research` | 조사 증거 필요; 계획/구현 없이 진행 |
| **증거는 충분하나 구현 전략 필요** | `/rpi-plan` | 일반적인 진행 경로 (가장 흔함) |
| **계획은 있고 구현 준비 완료** | `/rpi-implement` | 승인된 작업의 실행만 필요 |
| **구현 완료 후 검토/수용 필요** | `/rpi-review` | 변경 사항의 조정(reconciliation) 및 후속 라우팅 |
| **행동 전 가정 노출 필요** | `/rpi-challenger` | 의사결정 전 대안과 위험 검토 |
| **코드/산출물 이해 필요** | `/rpi-walkthrough` | 변경 전 기존 패턴 학습 |

### 선택 플로우차트

```
작업 정의됨?
├─ NO → 요구사항 수집 후 진행
└─ YES → 증거 준비 상태 평가

증거 충분?
├─ NO (주요 격차) → /rpi-research
└─ YES → 라이프사이클 필요?

라이프사이클 필요?
├─ 전체 워크플로 래퍼 → RPI Agent (Manual Mode)
├─ 조사만 → /rpi-research
├─ 계획만 → /rpi-plan
├─ 구현만 → /rpi-implement
├─ 리뷰만 → /rpi-review
├─ 가정 검토 → /rpi-challenger
└─ 학습 → /rpi-walkthrough
```

## 📝 Phase 3: 라이프사이클 명확화 (Lifecycle Clarification)

### 각 단계별 질문

#### 🔬 Research 단계 필요 확인
```
Q5. 다음 중 놓친 것이 있나요?
    ☐ 요구사항 명확성
    ☐ 종속성 이해
    ☐ 기존 패턴 검증
    ☐ 외부 통합 연구
    ☐ 아키텍처 결정
    
위 항목 2개 이상 YES → /rpi-research 시작
```

#### 📋 Plan 단계 필요 확인
```
Q6. 다음이 필요한가요?
    ☐ 작업 순서 및 의존성 명시화
    ☐ 구현 전략 검증
    ☐ 수용 기준 명확화
    ☐ 위험 요소 문서화
    ☐ 검증 방법 계획
    
1개 이상 YES → /rpi-plan 시작
```

#### ⚡ Implement 단계 준비
```
Q7. 구현 준비 상태?
    ☐ 계획 승인됨
    ☐ 수용 기준 명확함
    ☐ 종속성 확인됨
    ☐ 검증 방법 정의됨
    
전체 YES → /rpi-implement 시작
```

#### ✅ Review 단계 필요 확인
```
Q8. 리뷰/수용이 필요한가?
    ☐ 주요 변경사항
    ☐ 아키텍처 영향
    ☐ 공식 승인 필요
    ☐ 후속 작업 라우팅 필요
    
1개 이상 YES → /rpi-review 시작
```

## 💡 인터뷰 진행 팁

### DO ✅
- **증거 우선**: "이미 충분한 증거가 있나?"부터 시작
- **복잡도 평가**: 작업의 범위, 종속성, 불확실성 파악
- **명확성 확보**: 요구사항과 수용 기준이 명시적인지 확인
- **최소 경로**: 필요한 가장 작은 라이프사이클 개념 선택
- **맥락 보존**: `.copilot-tracking/` 산출물로 지속 추적

### DON'T ❌
- **과도한 계획**: 증거가 충분하면 계획 생략 가능
- **증거 재사용 무시**: 기존 조사 결과 재활용
- **단계 강요**: 모든 작업이 5단계를 다 필요로 하지 않음
- **맥락 손실**: 새 채팅 시 기존 산출물 참조 필수
