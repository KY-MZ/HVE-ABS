# 제출 주제 적합성 분석

**제출 주제 (원문 요약)**: Playwright 등 브라우저 캡처 스킬을 사용한 하네스 Wrapping 패키지, 슬로건 "Tenant MW Security 자동구성"

## 1. 사실 / 가정 / 미해결

| 구분 | 내용 |
|---|---|
| 사실 (documented) | 워크샵이 다루는 게시 경로는 ① Azure Managed Application ② Microsoft 365 Copilot 에이전트 두 가지 |
| 사실 (documented) | HVE Core 커스텀 에이전트는 M365 Copilot 에이전트가 아니며 Agent Store에 직접 업로드 불가 |
| 사실 (documented) | 게시 심사 관련 항목: 최소 권한, 동의 경계, 테넌트 관리자 승인, 프롬프트 인젝션 시나리오 테스트, 사람 에스컬레이션 |
| 가정 | 로컬 Playwright 패키지가 두 경로 중 하나로 포장 가능 → 미검증 |
| 가정 | 대상 설정 대부분이 API(Graph/PowerShell)로 변경 가능 → 항목별 미검증 ([[API-vs-UI-Coverage]]) |
| 미해결 | 최종 오퍼 유형, 가격, 대상 고객 |

## 2. 적합 점수표 (Inference, 정성 평가)

| 기준 | 평가 | 사유 |
|---|---|---|
| 도메인 적합 | 높음 | M365 보안 구성, 규제 산업 감사 증거 요구와 부합 |
| 재사용 IP | 높음 | 반복 가능한 구성/증적 워크플로 |
| 게시 경로 명확성 | 낮음 | 어느 오퍼 유형에도 직접 대응하지 않음 |
| 권한 모델 | 위험 | 브라우저 자동화는 관리자 세션의 광범위 권한을 쓰기 쉬움 |
| 변경 안전성 | 미흡 | 롤백·사전 영향 확인·적용 후 검증이 슬로건에 없음 |
| 슬로건 | 재작성 권장 | "자동구성" 단독은 고위험 변경으로 읽힘 |

## 3. 두 갈래 (Hypothesis, 확정 아님)

| 안 | 정의 | 위험도 | 포장 가능성 |
|---|---|---|---|
| A. 읽기 전용 구성 평가·증적 수집 | 설정을 읽어 베이스라인과 비교, 화면 증적은 Playwright로 보조 | 낮음 | 선언형 에이전트 또는 Managed Application 후보 |
| B. 승인 기반 자동구성 | 사람 승인 후 Graph/PowerShell 우선 적용, 롤백, Positive/Negative 검증 | 높음 | 요건 무거움, 후속 마일스톤 |

권장: **A를 P0(MVP), B를 후속**. 근거: 문서가 "승인된 첫 작업만 구현"과 "게시 준비는 MVP와 별개"를 요구한다.

## 4. 슬로건 후보 (초안)
- 보안 구성의 **검증 가능한** 증적 수집부터 승인 기반 적용까지
- 구현 수단(Playwright)은 슬로건이 아니라 솔루션 설명에 둔다.

## 5. 검증 계획 (최소 범위)

| 가설 | 필요 증거 | 방법 |
|---|---|---|
| 두 경로 중 하나로 포장 가능 | 현재 게시 매트릭스, Partner Center 요건 | 퍼실리테이터 질의 + Microsoft Learn 확인 |
| 대상 설정이 API로 가능 | 항목별 API/모듈 지원 | [[API-vs-UI-Coverage]] 표 작성 |
| 브라우저 증적이 심사에서 수용 | 게시 정책 | 확인 불가. 보조 수단으로만 쓴다 |
