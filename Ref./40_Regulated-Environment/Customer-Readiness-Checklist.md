# 고객 준비도 체크리스트 (도입 전 점검)

고객 환경이 우리 에이전트를 받아들일 수 있는지 **도입 전에** 확인한다. 각 항목은 `확인됨 / 미확인 / 불가`로 기록하고, 증거를 남긴다. 체크박스는 사람이 확인했을 때만 채운다.

## A. 라이선스·클라우드
- [ ] Microsoft 365 Copilot 또는 Copilot Chat 접근이 가능한 라이선스 (Copilot Chat은 일부 knowledge 소스 제한)
- [ ] 테넌트가 상용 클라우드인가, 정부 클라우드인가 (지원 범위가 다름)
- [ ] 데이터 레지던시 요건이 있는가 (Copilot 부분 / 백엔드 부분 구분)

## B. 에이전트 거버넌스 (Microsoft 365 관리 센터)
- [ ] Agents → Settings → User access: 대상 사용자·그룹에 허용
- [ ] 조직 제작 에이전트·플러그인 허용 설정 (사이드로드·조직 업로드 경로일 때)
- [ ] Teams 관리 센터의 사용자 지정 앱 정책이 설치를 막지 않음
- [ ] 관리자 요청 승인 절차 존재 (승인자 역할, 소요 시간)
- [ ] 관리자 검토용 자료 준비: 권한 목록, 호출 액션 목록, 데이터 흐름, 프라이버시 성명, 약관

## C. 네트워크 (고객 네트워크팀)
- [ ] Microsoft 365 및 Copilot 엔드포인트 허용
- [ ] `*.cloud.microsoft` 전체 허용 (일부만 허용하는 구성은 미지원)
- [ ] WSS 연결이 가능하고 TLS 검사나 프록시 타임아웃이 연결을 방해하지 않음
- [ ] 백엔드 ingress에 Copilot 정적 egress IP 목록 허용 (목록은 7일 사전 고지로 변경될 수 있음, 변경 추적 담당자 지정)
- [ ] 로그인·인증 트래픽은 별도 요건으로 확인

## D. 신원·권한
- [ ] Entra 앱 등록, 동의 절차(관리자 사전 동의 가능 여부)
- [ ] Conditional Access가 플러그인 SSO를 막지 않음 (미확인 영역, 파일럿에서 확인)
- [ ] 요구 권한은 읽기 전용 최소 집합, 권한 상승 요구 없음
- [ ] 관리 API 접근 조건(JIT 등)이 있다면 확인

## E. 데이터·감사
- [ ] 백엔드 저장 데이터 범위 합의(설정 메타데이터와 판정만)
- [ ] 보존 기간, 삭제 절차, 하위 수탁자 공시
- [ ] 고객 SIEM 또는 감사 시스템으로 로그 내보내기 방식
- [ ] DLP·레이블 정책과 충돌하지 않음

## F. 운영 모드 결정
- [ ] 모드 A (표준) / 모드 B (고객 경계 강화) / 모드 C (Copilot 불가) 중 선택
- [ ] 선택 사유와 승인자 기록
